KOTLIN-SPECIFIC RULES (learned from build failures):
  - ONE companion object per class — always merge constants
  - companion object contains ALL const val for the class
  - Never add a second companion object when appending code
  - When adding constants: search for existing companion first
  - Sealed class states: always data class or object, never raw
  - All constants referenced in the class body must exist in
    the single companion object before they are used

C# / .NET RULES (learned from EF Core test failures):
  - All nested model classes used as navigation properties
    MUST be marked [Owned] and registered via OwnsOne/OwnsMany
    in OnModelCreating
  - Nested owned types (e.g. PreloaderConfig inside
    ServiceModeDescriptor) must use nested OwnsOne lambdas
  - Build with /p:TreatWarningsAsErrors=true in CI

ERROR HANDLING:
  - All IO/hardware/network: wrapped in try/catch
  - Sealed classes for state — never raw String/Int
  - Never empty catch{}

SECURITY:
  - No hardcoded secrets, keys, credentials
  - PendingIntent on Android 12+:
    FLAG_MUTABLE + intent.setPackage(packageName)
  - Logs: [LEVEL][TAG] format — no raw PII ever

PERFORMANCE:
  - All USB/hardware ops: Dispatchers.IO — never main thread
  - Coroutines only — zero blocking calls on main thread
  - Single source of truth for all state (StateFlow)
